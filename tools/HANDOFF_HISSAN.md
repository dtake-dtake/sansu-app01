## 1. ここまでに確定・実装完了した仕様（たし算・ひき算・共通UI）

### A. 上部スタイル選択（3スタイルへの統合：案A）
1. **① 小3〜4 ノート風 (`s1`)**
   - **たし算**: 答えの行の「位の境界線上（左上）」に小さく繰り上がりメモを書く実戦的ノート仕様。
   - **ひき算**: 斜線で消した数字の「すぐ上（上段セル上端）」に小さく減った数を書くノート仕様。
2. **② 小2 導入風 (`s2`)**
   - 一番上の独立したメモ段に丸囲みで大きくメモを書く視覚的整理仕様。
   - プリセット選択時、学年（`grade: 2` vs `grade: 3, 4`）に応じて `s1` ⇔ `s2` が自動連動（手動切替も可）。
3. **③ 暗算・直打ち（メモなし） (`s3`)**
   - メモ枠を非表示にし、答えのマスのみをテンポよく直打ちする仕様。

### B. 共通操作・入力UX
- **全角・半角シームレス対応**: 日本語IME（全角モード）がONのままでも、物理キーコード（`Digit0`〜`9`, `Numpad0`〜`9`, `Period`, `NumpadDecimal`）や全角文字（`０`〜`９`, `．`, `。`）を即座に半角へ自動変換して1キーで入力・フォーカス移動。
- **矢印キー（`↑` `↓` `←` `→`）2次元空間ナビゲーション (`moveFocusByArrow`)**: どのスタイル・手順でも上下左右の隣接マス（答え⇔メモ、隣の位）へ自在に移動可能。
- **2けた〜5けた・小数プリセット拡張**: たし算・ひき算ともに2けた〜5けた、小数、空位（0）を含むプリセットを完備。
- **赤丸手順バッジの重なり防止**: 繰り上がり・繰り下がりメモ入力欄の真上（外側）にバッジを配置し、入力文字と絶対に重ならないレイアウトに統一。
- **開発用サーバーでの表示位置（スクロール位置）・状態の完全保持**:
  - すべての `.focus()` に `{ preventScroll: true }` を適用し、フォーカス時の勝手な画面ジャンプを防止。
  - `sessionStorage` と `history.replaceState` により、ブラウザ更新（F5）や設定変更時にもスクロール位置（`window.scrollY`）と選択中の問題・オプションを完全維持。

### C. たし算（`op = 'add'`）の確定仕様
1. **4大基本パターン（書く順番）**:
   - **① 小さい位から（答え → くり上がりメモ）** (`ans_rtl_memo_after`)
   - **② 小さい位から（くり上がりメモ → 答え）** (`ans_rtl_memo_before`)
     - ※同じ位の中で「先に左隣へのくり上がりメモ `1` を書いてから、その位の答えを書く」順序。
   - **③ 小さい位から（メモ無し）** (`ans_rtl_nomemo`)
   - **④ 大きい位から（メモ無し）** (`ans_ltr_nomemo`)
2. **一番上の位がくり上がったとき（例：`648 + 574 = 1222`）**:
   - **メモを書かず直接答えに書く (`direct`)** ／ **メモを書いてから答えに書く (`memo`)** をラジオボタンで選択可能。
3. **空位（上下ともに0の位）の扱い**:
   - 個別の例外オプションは設けず、4大基本パターンのルールに統一。

---

### D. ひき算（`op = 'sub'`）の確定仕様
1. **繰り下がりメモ方式の一本化**:
   - 2回以上の連続繰り下がり（`325 - 168` など）でメモが重なって破綻しやすい「10を書く」「合わせた数（12など）を書く」方式は廃止し、**「斜線で消して減った数のみを書く」方式に一本化**。
   - どの位も「右の位に1回貸す」ことしか起きないため、何けたのひき算でも1列につき最大1個のメモに収まる。
2. **3大基本パターン（書く順番）**:
   - **① 小さい位から（メモあり：斜線で消して減った数を書く）** (`sub_rtl_memo`)
     - 引けない位に出会った時点で上の位を斜線で消して減った数を書き（`0` を跨ぐ `302 - 165` 等では百の位 `2` → 十の位 `9` の順）、その位の答えを書いてから次の位へ進む（過去アプリ `2nen/56`, `3nen/41`, `3nen/42`, `3nen/43`, `4nen/092` と完全一致）。
   - **② 小さい位から（メモ無し）** (`sub_rtl_nomemo`)
   - **③ 大きい位から（メモ無し）** (`sub_ltr_nomemo`)

---

### E. 小数のひっ算＆先頭の「0」の扱い（たし算・ひき算共通）
1. **答えの小数点を打つタイミング（4択）**:
   - **初めに打つ (`before`)**: 手順①として最初に小数点を打つ。
   - **通り道で打つ (`pass`・デフォルト)**:
     - 小さい位からの場合：**小数第一位の処理が終わった直後（一の位へ進む通り道）** で打つ。
     - 大きい位からの場合：**一の位の答えを書いた直後（小数第一位へ進む通り道）** で打つ。
   - **最後に打つ (`after`)**: すべての数字を書き終えた最後に打つ。
   - **自動表示 (`auto`)**: 初めから小数点を表示し、数字のみを入力する。
2. **1より小さい小数（`0.38 + 0.45 = 0.83`, `3.24 - 2.56 = 0.68`）と整数の桁減少（`124 - 86 = 38`）**:
   - **小数の場合**: 一の位が `0` になっても **`0.` の `0` の入力を必須** とする。
   - **整数の場合**: 最上位が繰り下がりで `0` になった場合（`124 - 86 = 38`）は、答えの百の位に不要な `0` を書かせず空欄とする（百の位の繰り下がりメモ `0` のみ記録）。また、問題表示でも桁が少ない方の先頭に不要な `0`（`086` 等）は表示しない。
